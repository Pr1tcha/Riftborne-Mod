# Реворк системы сил под лор PS V2.5

Основано на `ONBOARDING_Project_Legion.md` (канон V2.5) и `MOD_Система_сил_механика.md`
(механическая спецификация). Документ — план перехода **фактического кода мода**
на новую модель. Ветка: `dev`.

## 0. Главный вывод

Текущая боевая система мода реализована под **старую** модель лора («производные
аспекты», V2). Прямое подтверждение — `RnaAspectResonance` (7 «латентных аспектов»)
и `RnaAffinityTag` (10 тегов): это словарь мёртвой модели. V2.5 её отменяет и ставит
лестницу `РНА → Основа → Примитивы → Грань → Огранка → Апекс` с Δ-осями и формулой
нагрузки.

Значит: **меняется ядро**, а не обёртка. Но значительная часть каркаса
переиспользуется (см. §2), поэтому это управляемый поэтапный переход, а не переписывание
с нуля.

## 1. Что уже есть в коде (факт)

- **Хранение:** ручной NBT под `Riftborne.RNA` / `Riftborne.RNA.Combat` через
  `RiftbornePlayerData`. `RnaData` — 4 параметра (все 0–100, включая connectivity),
  мета-износ 0–100 с 5 стадиями (`MetaWearStage`), путь формирования, флаги коллапса.
- **API:** `RnaApi` — init/reset/setStat/addStatGrowth/setFormationPath/meta-wear/collapse.
  Плотно завязан на Кодекс (уведомления, лента).
- **Боевой слой (`rna.combat`):** реестр способностей (`RnaAbilityRegistry`: Барьер,
  телекинез), `RnaLoadBand` (NORMAL/STRAIN/OVERHEAT/BREAKDOWN), прогрессия техник
  (`RnaTechniqueStage`: SEALED/DISCOVERED/STABILIZED/MASTERED + evidence + acquisition
  methods), `RnaAspectResonance` (7), `RnaAffinityTag` (10).
- **Тренировка:** Synchronization Node (`rna.combat.training`) — блок с мультиблок-
  разворачиванием, меню выбора (Этап 2), минигра тренировки Барьера.
- **Физподготовка (`physical`):** endurance/strength/motorics/stability, 0–100, дневной
  цикл. Сейчас питает только абстрактный «overload capacity».
- **Сеть/HUD:** `RnaCombatNetwork` (+ payload'ы), `RnaCombatClient` — бары нагрузки/износа.

## 2. Карта перехода старое → V2.5

| Текущее | V2.5 | Действие |
|---|---|---|
| `RnaData` 4 параметра, connectivity **0–100** | 4 параметра, connectivity **1–3 (C1–C3)** | Reframe: connectivity → C-класс; остальные остаются 0–100 |
| `FormationPath` (5, 3 выбираемых) | 5 путей со стартовым перекосом | Keep, донастроить; стартовый connectivity → C-класс |
| `MetaWearStage` + мета-износ | мета-износ + окно допустимости `f(meta_wear)` | Keep как регулятор; добавить `admissibility_window` |
| `RnaAffinityTag` (10) | **Δ-оси (7): dR/dE/dS/dG/dV/dSt/dP** | **Заменить** на enum из 7 осей |
| `RnaAspectResonance` (7 латентных аспектов) | аспекты мертвы → **Грань** (кристаллизация) | **Удалить** концепт; заменить Гранью |
| `RnaTechniqueStage` (4 стадии) | уровни исполнения примитива 1–4 + жизненный цикл Огранки | Reframe |
| `RnaAbilityRegistry` (Барьер, телекинез) | **9 примитивов (enum)** + **Огранки (датапак)** | Reframe способностей в примитивы/огранки |
| `RnaLoadBand` (4 полосы) | нагрузка vs throughput/окно | Keep, питать из `LoadCalculator` |
| — | **`LoadCalculator`** (формула L) | **Новое** |
| — | **4 гейта организма** (phys/mental/psych/genetic) | **Новое** — phys гейт цепляется к `physical`! |
| — | **Грань + Огранка + Апекс** (данные) | **Новое** |
| `physical` (4 стата) | гейт `phys` (потолок node_density + overload_res) | **Связать**: физсистема наконец получает смысл |
| Минигра Барьера @ Node | тренировка примитивов / кристаллизация @ Node | Перепрофилировать |
| Сеть/HUD combat | бары Нагрузка + Мета-износ | Перепрофилировать |

**Удачные стыки:** физподготовка → гейт `phys`; Synchronization Node → место практики
примитивов и кристаллизации грани; мета-износ → готовый регулятор «платишь навсегда» +
окно допустимости; HUD-каркас → бары Нагрузка/Износ.

## 3. Формула нагрузки (ядро баланса, из спеки §4)

```
L_total = (Σ базовых стоимостей задействованных Δ) × K_complex × K_depth × K_hold
```
Дефолтные числа спеки (принять как старт, вынести в конфиг):
- База Δ: dR=8, dE=10, dS=14, dG=18, dV=16, dP=14, dSt=20 (время дороже пространства).
- K_complex: C1=1.0, C2=1.8, C3=3.2 (нелинейно).
- K_depth: ур.1=1.0, ур.2=1.5, ур.3=2.3, ур.4=4.0.
- K_hold: миг=1.0, удержание≈1.6/сек.

Проверки на такт: `L > throughput` → перегруз (шум/штраф); `L > admissibility_window`
→ компенсация (сброс + откат); `activeΔ > connectivity` → нельзя скастовать; `activeΔ ≥ 4`
→ аномалия (игроку заблокировано).

## 4. Фазы (каждая компилируется и тестируется)

- **Ф1 — Модель данных.** `RNAProfile` (см. §5 решения), `DeltaAxis` (7), `Primitive` (9)
  как enum. Connectivity → C-класс + миграция. Компилируется, поведения ещё нет.
- **Ф2 — `LoadCalculator`.** Чистая функция формулы L. Тестируется без Minecraft.
- **Ф3 — Примитивы в мир.** Подключить ≥2 примитива (P1 Считывание, P3 Сдвиг) к реальным
  действиям → LoadCalculator → мета-износ/компенсация. Телекинез переосмыслить как
  P3/P2 (dG). Старый ability-путь для них отключить.
- **Ф4 — HUD.** Бар Нагрузки (быстрый) + бар Мета-износа (медленный) на базе текущей сети.
- **Ф5 — Гейты организма.** Связать `physical` как гейт `phys`; добавить mental/psych/
  genetic; гейты ограничивают рост параметров.
- **Ф6 — Кристаллизация грани.** Событие «стрессового скачка», трекинг доминантной Δ,
  запись `Facet`.
- **Ф7 — Огранки.** Датапак-реестр (JSON+Codec). Барьер → первая Огранка. Перенос минигры.
- **Ф8 — Апекс + регуляторы.** Компенсация, блок аномалии, полировка.
- **Ф9 — Миграция сейвов + чистка.** Удалить мёртвый код (aspect resonance, affinity tags,
  старая ability-модель), финальная миграция NBT, бамп версии.

## 5. Развилки (решает автор — влияют на всю реализацию)

   (меньше правок сейчас). Рекомендую Attachments, раз всё равно большой реворк.
2. **Судьба Барьера и телекинеза.** (а) Переосмыслить как огранки/применения примитивов и
   сохранить работу; (б) отложить и строить примитивы с нуля; (в) держать легаси параллельно
   на время перехода. Рекомендую (а).
3. **Порядок сборки.** Тонкий вертикальный срез (RNAProfile + LoadCalculator + 2 примитива +
   HUD) для проверки ощущения, потом грань/огранка/апекс — или строить полную модель сверху.
   Рекомендую вертикальный срез.

## 6. Риски

- **Connectivity 0–100 → 1–3** ломает существующие формулы (телекинез считает дистанцию/силу
  через connectivity 0–100) и сейвы. Нужна миграция + переформула.
- Реворк обесценивает часть недавней работы: реестр способностей, aspect resonance, affinity
  tags, стадии техник. Минигру Барьера можно перепрофилировать, но её текущая цель уходит.
- Кодекс плотно завязан на старые события РНА (`RnaApi` шлёт уведомления/ленту) — при смене
  модели править и тексты Кодекса.
- Δ-оси/примитивы как enum (не датапак) — правильно по спеке (это физика мира), но фиксирует
  баланс в коде; числа выносим в конфиг, чтобы крутить без пересборки.
